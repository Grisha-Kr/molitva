# Молитвенный дневник — заметки для Claude

Веб-приложение для молитвенных нужд, отметок дней молитвы и стихов. Владелец: Григорий (GitHub: Grisha-Kr). Пользователи: он и близкие, до 20 человек, регистрация по приглашению. Адрес: `https://molitva.grishaweb.ru`.

Устройство повторяет «Мою зачётку» (репозиторий Grisha-Kr/zachetka): там же `docs/context.md` с описанием сервера, домена и DNS. При изменениях в инфраструктуре обновлять и его.

Работа идёт этапами. Этап 1 (сделан): личный дневник. Правки 1.1 (сделаны): круглые фото с обрезкой, подразделы-вода, кнопка «Помолился» и стих дня, календарь молитв, значки «Молитва», лимит 250 МБ. Этап 2 (сделан): группы (общие нужды, неделя группы, «Поделиться ответом», пункт «Группы» в нижнем меню). Правки 2.1 (сделаны): у общей нужды «Помолился» за сегодня вместо «Молюсь», счётчик «Сегодня молились», неделя группы по отметкам в этой группе, личный дневник с группой не связан. Следующий шаг: вкладка «Материалы» в группе. Этап 3: почта для «Забыли пароль?», выгрузка и загрузка копии данных, календарь молитв за год.

## Общение с владельцем
- Только на русском. Английские слова и названия сопровождать переводом в скобках.
- Владелец не программист: объяснять простыми словами, команды давать готовыми к вставке, по одной задаче за раз, говорить, где выполнять (Mac или сервер).
- Без длинных тире, без эмодзи, без конструкций «не X, а Y», без пафоса и лишних повторов.
- Пароли нигде в коде и инструкциях не писать.

## Группы (этап 2, миграции 1772000000_groups.js и 1773000000_v21.js)
- `groups`: name (до 100), owner (создатель, relation без каскада), invite_code (24 символа, уникальный, генерирует сервер `newGroupCode`). list/view: участник (`group_members_via_group.user ?= @request.auth.id`); update и delete: создатель; create: нет (только маршрут). Хук при изменении через API оставляет прежние owner и invite_code: так создатель только переименовывает.
- `group_members`: group, user (оба каскадно), уникальная пара. list/view: участник той же группы (`group.group_members_via_group.user ?= @request.auth.id`). Создавать, менять и удалять через API нельзя: только маршруты.
- `group_needs`: group, need, added_by (каскадно), уникальная пара (group, need). Ссылка на нужду владельца, копии нет. create: своя нужда (правило) и вы участник группы (хук, он же ставит added_by); delete: владелец нужды. При удалении нужды или группы удаляется каскадом, при переносе нужды в другой раздел остаётся.
- `group_praying` (правки 2.1: «Помолился» у общей нужды за день): group_need, user, group (ставит сервер), date; уникальная тройка (group_need, user, date). list/view: участник группы. create: только за себя (правило `@request.body.user = @request.auth.id`), хук проверяет участие в группе нужды, что нужда не отвечена, повтор и дату; delete: только свою (правило), хук проверяет дату. Дата от «сегодня минус 1» до «сегодня плюс 1» по UTC сервера (`checkGroupDate`), приложение шлёт только сегодня по часам устройства. Старые записи «Молюсь» без даты миграция 2.1 удалила.
- `group_days` (правки 2.1): group, user, date (оба relation каскадно), уникальная тройка (group, user, date). День молитвы участника в группе, по нему строится неделя группы. list/view: участник группы; create, update, delete через API нельзя. Ставит хук создания `group_praying` (`markGroupDay`), снимает хук удаления, когда у участника за этот день в группе не осталось ни одной отметки (`unmarkGroupDay`). Хуки запросов срабатывают только на запросы API: каскадное удаление отметок при удалении общей нужды день не трогает, поэтому прошедшие дни остаются, если нужду убрали из группы, удалили или отметили отвеченной.
- `needs` list/view: `owner = @request.auth.id || group_needs_via_need.group.group_members_via_group.user ?= @request.auth.id`. Остальные правила нужд прежние (менять может только владелец).
- `users` list/view: сам человек или участники общих групп (`group_members_via_user.group.group_members_via_group.user ?= @request.auth.id`).
- Скрытие полей (`onRecordEnrich`, действует в списках, одиночных записях, expand и realtime): у чужой нужды убираются section, last_prayed_at, photo_crop, photo_size, а answer_note остаётся только при `answer_shared` и `answered_at`; у другого пользователя видны только id, name, avatar; invite_code видит только создатель.
- Фильтры и сортировка (`checkQuery` в lib.js) в коллекциях needs, users, groups, group_* (с 2.1 и group_days) для не-суперпользователя: только поля id, owner, user, group, need, group_need, added_by, date, created, updated, name, title. Подписки realtime с фильтром запрещены. Так нельзя подобрать скрытые поля через `filter`.
- Лимиты: 20 участников в группе, 10 групп у человека (`MAX_MEMBERS`, `MAX_GROUPS` в lib.js и app.js).
- Маршруты (все требуют входа пользователя): `POST /api/molitva/groups {name}` создать (создатель сразу участник); `GET /api/molitva/join/{code}` → `{id, name, owner, members, member, full}`; `POST /api/molitva/join/{code}` вступить; `POST /api/molitva/groups/{id}/link` новая ссылка (старая перестаёт работать); `POST .../owner {user}` передать роль создателя; `POST .../remove {user}` исключить; `POST .../leave` выйти (создатель с участниками должен сначала передать роль; один создатель = группа удаляется). Маршрут `group-days` (читал чужие `prayer_days`) в правках 2.1 удалён.
- Выход и исключение (`removeMember`): удаляются group_needs с added_by = человек, его group_praying и group_days в группе. Удаление аккаунта (`onRecordDelete` users, `handOverGroups`): группы создателя переходят к участнику, вступившему раньше всех, без участников удаляются.

## Логика на сервере (pb_hooks/main.pb.js, lib.js)
- Первый пользователь получает `role=admin`; остальные только с действующим кодом `invite` (регистр не важен), счётчик `uses` и список `used_by` растут.
- Глубина разделов не больше двух: родитель должен лежать на главной, раздел с подразделами нельзя положить внутрь. Непустой раздел (подразделы или нужды) не удаляется (onRecordDeleteRequest; при удалении аккаунта каскад идёт мимо этой проверки).
- Стихов не больше 7 на владельца. Новый пользователь сразу получает стих Исаии 48:21 (`onRecordAfterCreateSuccess`, `addDefaultVerse` в `lib.js`); миграция 1.1 добавила его тем, у кого не было ни одного стиха.
- Отметки дней (`prayer_days`): создавать и удалять можно только с датой от «сегодня минус 3» до «сегодня плюс 1» по UTC сервера (запас на часовые пояса). В приложении можно отмечать сегодня, вчера и позавчера.
- Лимит места `USER_QUOTA_MB` (по умолчанию 250) на сумму `need_files.size` + `needs.photo_size` + `sections.photo_size`. Размер фото считает `recordPhoto` в `lib.js`: у только что загруженного файла `getString` пустой, поэтому смотреть и `getUnsavedFiles`; размер уже сохранённого файла берётся из хранилища. Без `photo` сервер сам очищает `photo_round` и `photo_crop`. У файлов нужд разрешены расширения pdf, doc, docx и картинки.
- `GET /api/molitva/setup` → `{firstRun, owner, contact}`; `GET /api/molitva/usage` → `{used, quota}`.
- В обработчиках PocketBase код верхнего уровня файла недоступен: общие функции лежат в `lib.js` и подключаются через `require(`${__hooks}/lib.js`)` внутри обработчика.
- `APP_URL` из окружения пишется в настройки, `BEHIND_PROXY=1` включает доверие к X-Forwarded-For. Резервная копия базы в 3:00, хранится 14 (задаёт миграция).

## Клиент (pb_public/app.js)
- Ключи состояния: `sections, needs, files, prayers, verses, days, daily` (см. `PBN`; `daily` = `daily_verses`, только чтение) и групповые `groups, gmembers, glinks, gpray, gdays, people, shared` (`GKEYS`). `needs` = свои нужды (фильтр `owner = me`), `shared` = чужие нужды из общих групп (`owner != me`), `people` = пользователи из общих групп. `gpray` = `group_praying` с даты «вчера», `gdays` = `group_days` с понедельника текущей недели (фильтры в `LIST_FILTER`). При переходе в группы они перечитываются не чаще раза в минуту, после нажатия «Помолился» перечитывается `gdays`. Адаптер `col(key).doc(id).create/update/delete`. Загрузка всего при входе (`loadAll`), живые обновления через `subscribe('*')` (событие нужды раскладывается в needs или shared по владельцу; изменения groups/group_members/group_needs перечитывают все групповые ключи, `refreshGroups`), перезагрузка при возврате на вкладку.
- Экраны по адресу после `#`: `#/` главная, `#/s/ID` раздел, `#/n/ID` нужда (`?g=ID`: открыта из группы, «Назад» в группу), `#/new` (`?in=ID` для подраздела) и `#/edit/ID` форма раздела, `#/verses`, `#/answers`, `#/profile`, `#/groups` список групп, `#/g/ID` группа, `#/gn/ID` чужая общая нужда в режиме чтения (ID записи group_needs), `#/join/КОД` приглашение. Ссылка-приглашение `/?group=КОД`: код запоминается в `mol_join` (localStorage), без входа на экране входа объясняется, что делать, после входа открывается `#/join/КОД`. Кнопка «Назад» телефона работает сама.
- Окна групп через `openForm` (поля `check` и `checks`, `html`, `onClick` для кнопок `data-dlg`). Следующее окно после закрытия текущего открывать через `thenOpen`: событие close приходит не сразу.
- Группа: у общей нужды кнопка «Помолился» (`gPrayBtn`, класс `pray-btn` как на главной) ставит или снимает отметку `group_praying` за сегодня; счётчик «Сегодня молились: N» или «Сегодня ещё никто не молился» (`gCount`), нажатие открывает список молившихся сегодня. У отвеченной нужды вместо кнопки «Отвечено» и заметка при `answer_shared`. Неделя группы и «Сегодня молились X из Y» считаются по `gdays` этой группы; личные отметки дня на них не влияют, а отметка в группе не трогает `prayer_days` и `last_prayed_at`.
- День считается по часам устройства (`todayISO`). Кнопка «Помолился» в карточке недели ставит или снимает отметку только за сегодня. «Помолился» в нужде ставит `last_prayed_at` и отметку дня. Запись молитвы за сегодня тоже ставит отметку дня и обновляет `last_prayed_at`.
- Неделя на главной с понедельника по воскресенье текущей недели, будущие дни бледные. Нажатие открывает окно `#cal` «Мои молитвы»: месяц (сетка с понедельника) и год (12 маленьких месяцев). Отмечать можно только `canMark`: сегодня, вчера, позавчера. Окно закрывается крестиком, по фону, Esc и жестом «назад» (при открытии `history.pushState`).
- Мой стих на главной: `Math.floor(дней от 2026-01-01 / период) % количество`, «Не менять» = первый.
- Стих дня (`dailyVerse`): `дней от 2026-01-01 % количество` по `daily_verses` в порядке `sort`. Показывается внизу карточки недели, пока сегодня отмечено; мягко появляется сразу после отметки (при перерисовке анимация продолжается отрицательной задержкой).
- Нужды в разделе: по `last_prayed_at` (у новых по дате добавления), новые сверху; отвеченные внизу.
- Фото уменьшается в браузере до 1600 точек и сохраняется как JPEG; HEIC, который браузер не открывает, сохраняется как есть. Защищённые фото и файлы загружаются по токену `pb.files.getToken()`, фото держатся в памяти как blob-ссылки (`PH`, `photoSrc(запись, поле, миниатюра)`). PDF открывается в окне просмотра через pdf.js: в новой вкладке нельзя, PocketBase отдаёт файлы с `Content-Security-Policy: sandbox`.
- Перестановка камней, подразделов и стихов: режим «Переставить» со стрелками, порядок в поле `sort`.
