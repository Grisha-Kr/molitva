# Молитвенный дневник — заметки для Claude

Веб-приложение для молитвенных нужд, отметок дней молитвы и стихов. Владелец: Григорий (GitHub: Grisha-Kr). Пользователи: он и близкие, до 20 человек, регистрация по приглашению. Адрес: `https://molitva.grishaweb.ru`.

Устройство повторяет «Мою зачётку» (репозиторий Grisha-Kr/zachetka): там же `docs/context.md` с описанием сервера, домена и DNS. При изменениях в инфраструктуре обновлять и его.

Работа идёт этапами. Этап 1 (сделан): личный дневник. Этап 2: группы (общие нужды, «Молюсь», неделя группы, пункт «Группы» в нижнем меню). Этап 3: почта для «Забыли пароль?», выгрузка и загрузка копии данных, календарь молитв за год.

## Общение с владельцем
- Только на русском. Английские слова и названия сопровождать переводом в скобках.
- Владелец не программист: объяснять простыми словами, команды давать готовыми к вставке, по одной задаче за раз, говорить, где выполнять (Mac или сервер).
- Без длинных тире, без эмодзи, без конструкций «не X, а Y», без пафоса и лишних повторов.
- Пароли нигде в коде и инструкциях не писать.

## Стек

## Камни
- Исходник `pb_public/img/stone.png` (серый камень на белом фоне, 1536×1024). Рабочая картинка `pb_public/img/stone.webp` (800×381, около 60 КБ): белый фон вырезан заливкой от углов, края сглажены, обрезано по камню, камень осветлён (`255 - (255 - v) * 0.6`), чтобы при умножении цвет раздела не темнел слишком сильно.
- Подкраска: `.stone` = `background-color` раздела + `background-image` камня с `background-blend-mode: multiply`, форма по `mask-image` той же картинки. Под камнем `.stone-shadow`. Камень «+» = `#EDEAE3` с прозрачностью 60%.
- Палитра в `COLORS` в `app.js`: granite, moss, clay, slate, sand, basalt, marble, night (ключ хранится в `sections.color`). У sand и marble тёмная подпись, у остальных белая.

## Данные (pb_migrations/1770000000_init.js)
Изменения схемы только **новой** миграцией, старую не править: на сервере она уже применена.
- `users`: role (user/admin), verse_period (daily/every3/weekly/never), theme (auto/light/dark). Роль через API не меняется (updateRule).
- `invites`: code (уникальный), note, max_uses, uses, expires, created_by, used_by. Только `role = "admin"`. created_by, uses и used_by ставит сервер.
- `sections`: owner, name, color, parent (relation на sections, пусто = на главной), sort.
- `needs`: owner, section (обязательная, каскадно), title, description, photo (protected, jpg/png/webp/heic до 10 МБ, миниатюры 120x120 и 800x0), photo_size (считает сервер), answered_at, answer_note, last_prayed_at.
- `need_files`: owner, need (каскадно), file (protected до 20 МБ), name, ext, size (считает сервер).
- `prayers`: owner, need (каскадно), date, text.
- `prayer_days`: user, date; уникальный индекс (user, date). Изменять нельзя, только ставить и снимать.
- `verses`: owner, text, ref, sort.
- У всех autodate `created`, `updated`. Даты строками `YYYY-MM-DD` (поля с pattern). id 15 символов генерирует клиент (`newId`).
- Правила: владелец видит и меняет только своё; связь на запись другой коллекции разрешена только на свою (`@request.body.X.owner = @request.auth.id`). Удаление нужды каскадом удаляет её записи молитв и файлы; удаление пользователя удаляет всё.
- **Этап 2:** правила `needs` (list/view) и `prayer_days` (list/view) расширить на участников общих групп новой миграцией. `prayers` и `need_files` остаются только у владельца, всегда.

## Логика на сервере (pb_hooks/main.pb.js, lib.js)
- Первый пользователь получает `role=admin`; остальные только с действующим кодом `invite` (регистр не важен), счётчик `uses` и список `used_by` растут.
- Глубина разделов не больше двух: родитель должен лежать на главной, раздел с подразделами нельзя положить внутрь. Непустой раздел (подразделы или нужды) не удаляется (onRecordDeleteRequest; при удалении аккаунта каскад идёт мимо этой проверки).
- Стихов не больше 7 на владельца.
- Лимит места `USER_QUOTA_MB` (по умолчанию 500) на сумму `need_files.size` + `needs.photo_size`. У файлов нужд разрешены расширения pdf, doc, docx и картинки.
- `GET /api/molitva/setup` → `{firstRun, owner, contact}`; `GET /api/molitva/usage` → `{used, quota}`.
- В обработчиках PocketBase код верхнего уровня файла недоступен: общие функции лежат в `lib.js` и подключаются через `require(`${__hooks}/lib.js`)` внутри обработчика.
- `APP_URL` из окружения пишется в настройки, `BEHIND_PROXY=1` включает доверие к X-Forwarded-For. Резервная копия базы в 3:00, хранится 14 (задаёт миграция).

## Клиент (pb_public/app.js)
- Ключи состояния: `sections, needs, files, prayers, verses, days` (см. `PBN`). Адаптер `col(key).doc(id).create/update/delete`. Загрузка всего при входе (`loadAll`), живые обновления через `subscribe('*')`, перезагрузка при возврате на вкладку.
- Экраны по адресу после `#`: `#/` главная, `#/s/ID` раздел, `#/n/ID` нужда, `#/new` (`?in=ID` для подраздела) и `#/edit/ID` форма раздела, `#/verses`, `#/answers`, `#/profile`. Кнопка «Назад» телефона работает сама.
- День считается по часам устройства (`todayISO`). «Сегодня молился» ставит или снимает отметку только за сегодня. «Помолился» в нужде ставит `last_prayed_at` и отметку дня. Запись молитвы за сегодня тоже ставит отметку дня и обновляет `last_prayed_at`.
- Стих на главной: `Math.floor(дней от 2026-01-01 / период) % количество`, «Не менять» = первый.
- Нужды в разделе: по `last_prayed_at` (у новых по дате добавления), новые сверху; отвеченные внизу.
- Фото уменьшается в браузере до 1600 точек и сохраняется как JPEG; HEIC, который браузер не открывает, сохраняется как есть. Защищённые фото и файлы загружаются по токену `pb.files.getToken()`, фото держатся в памяти как blob-ссылки (`PH`). PDF открывается в окне просмотра через pdf.js: в новой вкладке нельзя, PocketBase отдаёт файлы с `Content-Security-Policy: sandbox`.
- Перестановка камней и стихов: режим «Переставить» со стрелками, порядок в поле `sort`.

## Сервер и выкладка
- Сервер: AdminVPS, Ubuntu 24.04, IP 168.113.170.172. Рядом работает «Зачётка» (порт 8090).
- Приложение: папка `/opt/molitva` (код `src`, данные `pb_data`, настройки `molitva.env`), пользователь и служба systemd `molitva`, PocketBase на `127.0.0.1:8091`, файл `/etc/caddy/sites/molitva.caddy` с `protocols tls1.2 tls1.2`.
- `deploy/install.sh` общий `/etc/caddy/Caddyfile` не трогает: если в нём нет `import /etc/caddy/sites/*.caddy`, останавливается. После добавления сайта `caddy validate` и `systemctl reload caddy`; при ошибке проверки файл сайта убирается.
- Установка: `curl -fsSL https://raw.githubusercontent.com/Grisha-Kr/molitva/main/deploy/install.sh | bash -s -- molitva.grishaweb.ru me@grishakr.ru "Григорий Кривобок"`.
- Обновление: `bash /opt/molitva/src/deploy/update.sh` (копия базы, git pull, перезапуск).
- В скриптах `git -c safe.directory=/opt/molitva/src`.
